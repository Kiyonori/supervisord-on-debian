# 🍥 Debian PHP イメージを用いた定期処理の構築例

このリポジトリでは、Debian ベースの PHP コンテナ上で、supervisord を用いて安全に cron 定期処理を実行するための最小構成例を示します。
supervisord を用いることで、Linux の cron と同等の処理を Docker コンテナ内で実現します。なお Debian での supervisord
は環境構築に少しクセがあります。私自身が環境構築時に実際に詰まり、そして解決に至ったその要点だけを主に実装ベースとして簡潔にまとめています。

## 👩‍💻 想定ユースケース

<p>定期的な処理をサーバーサイドで実行します。</p>

例えば・・定期的な

- バッチ処理
- ログ集計
- 不要ファイル削除

<p>が考えられます。</p>

## 🏗️ 環境構築の方法

### 💡 環境構築

```bash
make up
```

<p>このコマンド1つで、環境構築が開始します。環境構築が完了すると、自動的に1分ごとに <code>code/output.txt</code> ファイルにタイムスタンプが記録されます。</p>

### 🚮 環境の破棄

```bash
docker compose down
```

## 🐳 supervisord コンテナ内

### 🧒 標準ユーザー

<p>環境構築時に <code>app-user</code> という名前の標準ユーザーを構築時に自動的に作成します。</p>

### ⏰️ supervisord プロセス

- 必ず root ユーザで実行します。
- プロセス本体は root ユーザーで実行されますが、定期処理は `app-user` で実行されます。

#### 👩‍🏫 なぜ定期処理を root で実行しないのか

- Docker コンテナ内の `app-user` と、ホスト OS 側のログインユーザーは、 環境構築時に UID / GID を合わせる形で自動的に対応付けを行っています。
- これにより、Docker コンテナ内で作成されたファイルが ホスト OS 側から <u>アクセスできなくなる問題 (注1)</u> を回避しています。

(注1) この現象は Docker がネイティブで稼働する Linux で顕著になります。

## 🔧 supervisor 設定ファイルの配置

| ファイルPath                         | パーミッション | 所有者:グループ  | 備考                             |
|----------------------------------|---------|-----------|--------------------------------|
| /etc/supervisor/conf.d/cron.conf | 0644    | root:root |                                |
| /etc/cron.d/my-cron              | 0644    | root:root | 所有者ならびにグループは root:root に設定すること |

## ⚠️ 注意事項

- 本リポジトリは構築例を示すことを目的としており、本番利用時は要件に応じた調整が必要です。
- `my-cron` ファイルの内容や実行頻度は要件に応じて適切に設定してください。
